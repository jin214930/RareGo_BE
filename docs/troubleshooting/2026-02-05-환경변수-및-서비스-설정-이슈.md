## 1. notification-service 시작 실패

### 증상
```
Provider ID must be specified for client registration 'kakao'
```

### 원인
`docker-compose.yml`에서 notification-service에 **불필요한 OAuth2 환경변수**가 복사되어 있었음.
```yaml
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_KAKAO_CLIENT_ID: ${KAKAO_CLIENT}
```
Kakao는 기본 provider가 아니라서 provider 설정 없이 client-id만 있으면 에러 발생.

### 해결
notification-service에서 OAuth2 관련 환경변수 제거:
```yaml
# 삭제된 환경변수
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_ID
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_SECRET
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_KAKAO_CLIENT_ID
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_NAVER_CLIENT_ID
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_NAVER_CLIENT_SECRET
```

### 교훈
- 각 서비스에 필요한 환경변수만 주입할 것
- 복사-붙여넣기로 환경변수를 공유하지 말 것

## 3. auth-service → member-service API 호출 실패

### 증상
```
UnknownContentTypeException: no suitable HttpMessageConverter found 
for response type [...] and content type [text/html]
```

### 원인
1. nginx 컨테이너에 **커스텀 설정이 마운트되지 않음**
2. `/api/v1/internal/members` 경로가 라우팅되지 않아 HTML 에러 페이지 반환

### 진단 명령어
```bash
# nginx 설정 확인 (잘못된 경로)
docker exec rarego-nginx cat /etc/nginx/nginx.conf

# nginx 설정 확인 (올바른 경로)
docker exec rarego-nginx cat /etc/nginx/conf.d/default.conf | grep -A5 "internal"
```

### 해결
```bash
docker compose up -d nginx --force-recreate
```

### 교훈
- nginx 설정은 `/etc/nginx/conf.d/default.conf`로 마운트됨
- 변경 후 반드시 `--force-recreate` 필요

## 4. DB 스키마 불일치 (revoked, refresh_token_hash 컬럼)

### 증상
```
Field 'revoked' doesn't have a default value
# 또는
Field 'refresh_token_hash' doesn't have a default value
```

### 원인
`RefreshToken` 엔티티에서 해당 필드들이 삭제됐지만, DB 테이블에는 아직 컬럼이 남아있고 `NOT NULL`로 설정되어 있어 Insert 시 에러 발생.

### 해결 (EC2에서 실행)
```bash
# 1. revoked 컬럼 삭제
docker exec -it rarego-mysql mysql -u rarego -prarego rarego \
  -e "ALTER TABLE auth_refresh_token DROP COLUMN revoked;"

# 2. refresh_token_hash 컬럼 삭제
docker exec -it rarego-mysql mysql -u rarego -prarego rarego \
  -e "ALTER TABLE auth_refresh_token DROP COLUMN refresh_token_hash;"
```

### 교훈
- 엔티티 필드 삭제 시 DB 마이그레이션 필수
- Flyway/Liquibase 같은 마이그레이션 도구 도입 권장

## 5. Grafana sub-path 설정 누락

### 증상
`https://rarego.duckdns.org/grafana/` 접속 시 `https://rarego.duckdns.org/login`으로 리다이렉트

### 원인
Grafana가 sub-path(`/grafana/`)에서 서빙되는데, `GF_SERVER_ROOT_URL`과 `GF_SERVER_SERVE_FROM_SUB_PATH` 설정이 없어서 Grafana가 `/login`으로 리다이렉트하면 nginx가 **프론트엔드의 /login**으로 보냄.

### 진단
```bash
# Grafana 직접 접근
curl -I http://localhost:3001
# 결과: Location: /login (Grafana 자체 리다이렉트)
```

### 해결
`docker-compose.yml`에 환경변수 추가:
```yaml
grafana:
  environment:
    GF_SERVER_ROOT_URL: ${GF_SERVER_ROOT_URL:-https://rarego.duckdns.org/grafana/}
    GF_SERVER_SERVE_FROM_SUB_PATH: ${GF_SERVER_SERVE_FROM_SUB_PATH:-true}
```

### 교훈
- CI/CD에서 `.env`에 값을 넣더라도 `docker-compose.yml`에서 참조해야 적용됨
- sub-path로 서비스 운영 시 해당 서비스의 root URL 설정 필수

## 6. OAuth2 로그인 후 localhost:3000 리다이렉트 이슈

### 증상
배포 환경(`rarego.duckdns.org`)에서 로그인 성공 시 `http://localhost:3000/auth/callback?...` 으로 리다이렉트되어 페이지를 찾을 수 없음.

### 원인
`auth-service`의 `CustomOAuth2SuccessHandler`에서 사용하는 `frontUrl` 설정이 `FRONT_URL` 환경변수 미설정 시 기본값인 `http://localhost:3000`으로 작동함.

### 해결
1. `auth-service`의 `application.yml`에 `frontUrl` 설정 추가
2. `docker-compose.yml`의 모든 백엔드 서비스 환경변수에 `FRONT_URL` 추가
   - **기본값**: `http://localhost:3000` (로컬 개발 편의성)
   - **배포 환경**: CI/CD 설정을 통해 `https://rarego.duckdns.org` 주입

### 교훈
- 외부 도메인과 연동되는 리다이렉트 URL은 환경변수로 관리하되, 기본값은 개발자가 가장 많이 사용하는 개발 환경(`localhost`)으로 설정하는 것이 휴먼 에러를 줄일 수 있음.
